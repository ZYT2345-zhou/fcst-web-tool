# FCST Web Tool · 计划工作台

把 PSI、提货跟进表、主数据、FCST 总表模板这几个 Excel 自动合并成一张 **FCST 总表** 的 Streamlit 网页工具。

不需要装 Excel 插件、不需要记公式：选工具 → 传文件 → 点生成 → 下载总表。

---

## 一、目录里都是什么

| 文件 | 作用 | 你需要关心吗 |
| --- | --- | --- |
| `planning_workbench.py` | **统一入口**。带登录、四个工具卡片、文件上传、结果预览和下载 | 启动时用它（主文件名） |
| `app.py` | 工具 01 的计算脚本（常规总表） | 只读，改逻辑才动 |
| `month_end_app.py` | 工具 02 的计算脚本（月末总表） | 只读 |
| `Separation of TOB and TOC dmd app.py` | 工具 03 的计算脚本（常规 · 客户类型） | 只读 |
| `Separation of TOB and TOC dmd app month_end.py` | 工具 04 的计算脚本（月末 · 客户类型） | 只读 |
| `requirements.txt` | Python 依赖清单 | 加依赖时才动 |
| `make_sample_data.py` | 生成一套假的练习数据（每个工具一个子目录） | 新手练手用，可删 |
| `.streamlit/config.toml` | 服务配置（上传上限 200MB 等） | 一般不用动 |
| `.streamlit/secrets.toml.example` | 密码配置样例，复制成 `secrets.toml` 用 | 本地跑才需要 |

> 结构逻辑：`planning_workbench.py` **只做界面和路由**，真正的计算仍然调用四个原脚本里的 `build_forecast_workbook()`。所以四个原脚本可以单独跑，也可以被工作台调用，逻辑只有一份。

## 二、四个工具怎么选

| # | 工具 | 什么时候用 | 要用到的提货表 |
| --- | --- | --- | --- |
| 01 | 常规总表 | 月初，只要「当月 + 未来 5 个月」 | 1 张（当月） |
| 02 | 月末总表 | 月末，要「当月 + 次月 + 后续 4 个月」 | 2 张（当月、次月） |
| 03 | 常规 · 客户类型 | 同 01，但要把当月提货拆成 TO-B / TO-C / TO-MKT | 1 张（含「客户类型」列） |
| 04 | 月末 · 客户类型 | 同 02，但要把当月与次月提货都拆成三类 | 2 张（含「客户类型」列） |

**月份口径**

- 工具 01 / 03：当月取自提货表的 `m_0`，PSI 提供 `m_1`～`m_5`。
- 工具 02 / 04：当月取自提货表 `m_0`，次月取自 `m_1`，PSI 只需提供 `m_2`～`m_5`。

---

## 三、每个文件必须有哪些列

| 文件 | 必需列 |
| --- | --- |
| PSI 文件（常规） | `SKU`、`品牌`、`m_1`、`m_2`、`m_3`、`m_4`、`m_5` |
| PSI 文件（月末） | `SKU`、`品牌`、`m_2`、`m_3`、`m_4`、`m_5` |
| 当月提货跟进表（常规） | `SKU`、`品牌`、`m_0`、`m_0安全库存` |
| 当月提货跟进表（客户类型） | `SKU`、`品牌`、`客户类型`、`m_0`、`m_0安全库存` |
| 次月提货跟进表（月末） | `SKU`、`品牌`、`m_1`、`m_1安全库存` |
| FCST 总表模板 | `Key`（还可以带上次的「X月需求总和(包含安全库存)(MMDD)」列，用来算差异） |
| 主数据 | `SKU`、`品牌`、`BU`、`项目号`、`物料编码`、`系列`、`版本` |

**列名要一字不差**（含冒号、空格、大小写）。少列会直接报「XX 缺少必需列：…」，改完再传。

## 四、本地运行

```bash
pip install -r requirements.txt
streamlit run planning_workbench.py
```

- 浏览器会自动打开 <http://localhost:8501>
- 需要访问密码。三种给密码的方式，任选一种：
  1. 环境变量：`APP_PASSWORD=你的密码 streamlit run planning_workbench.py`
  2. 复制 `.streamlit/secrets.toml.example` 为 `.streamlit/secrets.toml`，填 `APP_PASSWORD = "你的密码"`
  3. Streamlit Cloud 后台的 Settings → Secrets

> 没配密码时，`planning_workbench.py` 会直接报错提示你先设置；四个原脚本则只给个警告、不拦截。

### 第一次用，先拿假数据练手

不想拿真实数据试错的话，直接生成一套假的：

```bash
python make_sample_data.py
```

会在桌面生成 `fcst-示例数据/`，里面按工具分了四个子目录，文件名前面的数字就是网页上上传框的顺序：

```
01-常规总表/          1-PSI文件.xlsx  2-当月提货跟进表.xlsx  4-FCST总表模板.xlsx  5-主数据.xlsx  + 生成结果示例.xlsx
02-月末总表/          多一个 3-次月提货跟进表.xlsx
03-常规-客户类型/     提货表里多一列「客户类型」
04-月末-客户类型/     3、4 的合集
```

每个目录里的 `生成结果示例.xlsx` 是脚本自己跑出来的正确结果，可以拿来对照你生成的对不对。
这些文件全是随机造的，不含任何真实业务信息，用完直接删掉即可。

## 五、部署到 Streamlit Community Cloud

1. 把本仓库推到 GitHub（建议 **私有仓库**，见第六节）。
2. 打开 <https://share.streamlit.io>，用 GitHub 账号登录并授权。
3. **New app** → 选择本仓库、分支 `main`。
4. **Main file path** 填 `planning_workbench.py`（不是 `app.py`）。
5. 展开 **Advanced settings → Secrets**，填：

   ```toml
   APP_PASSWORD = "你们的团队密码"
   ```

6. 点 **Deploy**，等 1～3 分钟，拿到 `https://xxx.streamlit.app` 链接即可分享给同事。

> 之后每次 `git push` 到 `main`，线上会自动重新部署。

## 六、安全注意事项

- **不要把真实业务数据提交到仓库。** `.gitignore` 已忽略 `*.xlsx / *.xls / *.xlsm / *.csv`，请保持。数据只在浏览器里上传、内存里计算。
- **不要把密码写进代码。** `.streamlit/secrets.toml` 已被忽略，密码只放本地文件或平台 Secrets。
- 本工具包含公司供应链口径逻辑（品牌映射、BU 归类、客户类型拆分等），**建议仓库保持私有**。
- 主数据与提货表的 SKU / 品牌会做「品牌+SKU」拼接成 `Key` 再关联，避免不同品牌同款 SKU 串数据。

## 七、结果列怎么看

生成的总表里，带日期的列都是 **生成日期（MMDD）** 打标，例如：

- `7月预计总提货(0716)` —— 当月提货表汇总
- `7月安全库存(0716)`
- `7月需求总和(包含安全库存)(0716)` —— 前两者相加，**这是核心口径**
- `8月需求(0716)` … `12月需求(0716)` —— 来自 PSI
- `7月与上次的差异` —— 本次需求总和 与 模板里上次版本列 的差
- `key for sheet` —— 「销售大区-品牌-BU 预测MMDD」拼出来的分表标识

生成后在页面上可以**先预览、再下载**，不需要的可以直接清空当前工具重来。
